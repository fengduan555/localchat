# 艾莉 · 本地语音聊天（LLM → Kokoro 中文 → RVC 若叶睦 → 网页播放）

## 架构

    浏览器(打字,听声音) ──HTTP/SSE──▶ app.py (8770)
                                        ├─ LLM (OpenAI 兼容流式, key 自填)
                                        ├─ 分句 ──▶ tts_server (8765)
                                        │             ├─ 本地 Kokoro 中文 (CPU ~1.2s/句)
                                        │             └─ Windows RVC 服务 (8766, GPU ~0.2s/句)
                                        └─ SSE 回传音频 → 浏览器队列顺序播放

## 启动

    bash /home/fengduan/kokoro-tts/local_chat/run.sh

然后浏览器打开 **http://localhost:8770**

## 配置

左侧栏两栏设置，点“保存”即生效（存到 `local_chat/config.json`）：

**语音设置**
- 音色模型：airi_e360（若叶睦，自训）/ 12 个下载的现成角色模型（爱莉希雅、三月七、雷电将军…）
- 音色：airi（中文）/ airi_en（英语）
- 语速：0.6~1.6
- 索引倍率：0~0.7（>0 时用训练集索引，音色更稳、可压电音）

**LLM 设置**
- Base URL：填到 `/v1` 为止，例如 `https://api.deepseek.com/v1`
- API Key、模型名（如 `deepseek-chat`）
- 人设（System Prompt）、温度、最大长度

未填 LLM 时会走“演示模式”（固定文案），用来验证语音链路。

## 音色链路（OpenVoice 已移除）

```
文字 ──▶ 本地 Kokoro 中文合成 (CPU, ~0.8s)
          ──▶ Windows RVC 变声 (GPU, ~0.2s) ──▶ 24kHz wav
```

- **只保留两条链路**：本地 Kokoro 中文（离线）/ Kokoro 英文 + RVC 音色转换
- **已移除 OpenVoice**（2026-09 清理）：原来用于 Neurosama 音色克隆，现由 RVC 完全覆盖
  - 删除内容：`OpenVoice/` 目录（133MB）、`voice_registry/`、`ToneColorConverter` 相关代码约 12KB
  - 移除的端点：`POST /v1/voice/register`、`GET /v1/voice/{name}/profile`、`DELETE /v1/voice/{name}`
  - 旧音色备份：`backup/openvoice-legacy-*.tar.gz`（含 neurosama 音色档，仅留存，不再被加载）
- 音色切换：前端选 `assets/weights/*.pth` → 写 `model.txt` → RVC 服务热切换（LRU 缓存最近 2 个）

## 记忆系统（SQLite 本地存储）

```
local_chat/data/memory.db
├── sessions   会话（标题/创建时间/摘要）
├── messages   全部消息（永久保存，刷新/重启不丢）
└── facts      结构化事实记忆（key-value + 分类 + 证据 + 命中次数）
```

**三层记忆**

| 层 | 内容 | 实现 |
|---|---|---|
| 短期 | 最近 N 轮原文（默认 8） | 从 `messages` 读取 |
| **事实** | "用户称呼=阿风""讨厌的食物=香菜" | 每轮**后台线程**用 LLM 抽取 → 去重覆盖 → 注入 prompt |
| 中期 | 会话摘要（超 24 条自动生成并合并） | `sessions.summary` |

**时间感知**：每次请求注入"现在时间 + 距上次对话多久"，所以她会说"都三天没来找我了"。

**关键设计**
- 抽取/摘要全部走后台线程，**不增加回复延迟**（实测聊天时页面响应 1.5 毫秒）
- 注入硬上限 700 字符，防挤占人设与近期对话
- 事实必须带**原文证据**才写入，可在侧栏面板查看/删除/置顶
- 记忆注入 = 会随 LLM 请求发送给服务商（DeepSeek），敏感信息请勿录入
- 会话自动切分：距上次消息超过 2 小时自动开新会话；也可手动「新会话」

**关系状态（情绪连续性）**

每轮互动会小幅改变关系状态（与事实抽取共用**同一次 LLM 调用**，不增加延迟）：

| 状态 | 范围 | 说明 |
|---|---|---|
| 好感度 affinity | 0~100 | 被关心/夸赞/分享心事 → 涨；被冷落/敷衍/冒犯 → 跌 |
| 信任 trust | 0~100 | 透露私密/依赖她 → 涨 |
| 心情 mood | 10 种 | 开心/兴奋/害羞/平静/温柔/低落/寂寞/生气/担心/撒娇 |
| 纪念 milestone | ≤20 条 | 第一次互报名字、约定某件事等自动记录 |
| 内心话 note | 一句 | 她对自己状态的想法 |

状态会注入 prompt → **语气随情绪变化**（实测：热情关心后说"我今天超开心的"，被冷落后说"对不起嘛，那阿先忙…"）。
调整幅度倍率：`memory.mood_swing`（调小更稳）；`memory.model` 可单独指定记忆用模型。

> ⚠️ **记忆/摘要模型不能用推理模型**（如 `deepseek-flash`、`deepseek-reasoner`）：
> 它们会把 max_tokens 全花在 reasoning 上、返回空 content。默认用 `deepseek-chat`。

**侧栏面板**
- 「会话」：下拉切换 / 新会话 / 重命名 / 删除（刷新后自动恢复上次会话）
- 「记忆」：事实列表（★ 置顶、✕ 删除、显示分类与命中次数）/ 手动添加 / 导出 Markdown / 清空

## 关页自动停止服务

默认开启：**关闭网页后，后台服务（聊天 8770 / TTS 8765 / RVC 8766）会自动全部停止。**

原理（避免"刷新就误停"）：

```
网页每 5 秒 → POST /api/heartbeat   (有心跳 = 保持运行)
关闭/刷新时 → POST /api/bye         (sendBeacon)
后台看门狗 → 若 bye 后超过宽限期(默认20秒)仍无新心跳 → 执行 stop_all.sh 并自我退出
                 ↑ 刷新会在宽限期内重新发心跳 → 自动取消停止
```

- **想关闭该功能**：侧栏「服务」区取消勾选 *关闭网页后自动停止服务*（或把宽限期调大）
- **手动停止**：双击桌面「停止艾莉语音」（按端口精确结束，不会误关 RVC WebUI）
- **注意**：关页停服务后，下次要用请**双击桌面「艾莉语音聊天」**重新启动

## 观测

- 聊天服务日志：`app.log`（`[CHAT]`/`[TTS]`/`[WARM]`/`[AUTOSTOP]`）
- TTS 服务日志：`../rvc_work/tts_server.log`（`[HTTP 时间]`、`[TIMING] 基础语音 + RVC`）
- 状态栏显示：首句出声耗时 / 本轮总耗时

## 说明 / 已知限制

- 逐句流水线：LLM 还在写下一句时，前一句已在合成；短句稳态 **0.25~0.3 秒**，20 字左右约 1.1 秒
- 所有阻塞调用都在线程里执行，**合成繁忙时网页依然秒开**（已实测：并发合成期间页面响应 1~2 毫秒）
- 切换音色后的**第一句约 3 秒**（重建 CUDA Graph），之后回到 ~0.2s；用过的音色有 LRU 缓存
- 同一时刻 RVC 转换串行（单 GPU），多句会自动排队
- 语音服务依赖：WSL 里的 tts_server(8765) + Windows 侧 RVC(8766)
- 若切换模型后首个请求较慢，属正常现象
